## Specs

- **S1 — Edit quantities of a reserved order.** Client: "Mira al darle en un pedido Reservado ... Que nos permita editar la cantidad de producto y poner un buscador para por si quiere otro producto de inmediato agregarlo por Fas". Decision (L2): in the counter order dialog of a «Reservado» (unexpired) order, each line's quantity (cajas + piezas) can be raised, lowered or the line removed, and another product can be added with the existing search (nov14 S3). Raising/adding keeps nov14 rules (FIFO reserve, availability check, raised line keeps frozen unit price, new line priced like a new order). Lowering releases the reserved units back to their lots (lots.reserved stays equal to the Reservado allocations); removing a line releases all of it. The last remaining line cannot be removed (use «Cancelar pedido»). The order total updates. Any invalid change (not Reservado, expired, short stock, empty order) is rejected and nothing changes.
- **S2 — Supplier filter in «Nuevo reparto».** Client: "Aquí se requiere que solo dejes producto de LALA .. ya que Alpura no entra a reparto por el momento". User: "que deje filtrar por proveedor por si acaso efectivamente luego si se puede repartir alpura". Decision (L2): the new-assignment dialog has a «Proveedor» filter over the product picker; it starts on the supplier named LALA (case-insensitive) when it exists, otherwise «Todos»; the user can switch to another supplier or «Todos». Filtering only narrows the picker; the server keeps accepting any product.
- **S3 — Numeric fields reject letters.** Client: "De preferencia que no deje capturar letras en los campos que van números .." and "Letras .." (Liquidar reparto). Decision (L2): app-wide, every quantity field accepts only digits and every money/decimal field accepts only digits and one decimal point (max 2 decimals); typed or pasted letters are dropped as the user types. Submit-time validation stays.
- **S4 — Recarga of an open assignment.** Client: "Por este lado se requiere otro botón para hacer recarga ( agregar producto extra para este mismo día )". Decision (L6): an «En ruta» assignment can be topped up: a «Recargar» action opens a dialog like «Nuevo reparto» (Proveedor filter LALA by default, product search, cajas/unidades, digits only) and the loaded units are added to that same assignment (existing line raised or new line added), taken from the warehouse with the same availability rules as assigning. Settlement covers everything together; the settle dialog shows the assigned total. A rejected recarga changes nothing. Only «En ruta» assignments can be topped up.
- **S5 — Prepare the next assignment from what came back.** Client: "Esta ruta ya se líquido y ya está OK ... Ahora puedes hacer que aparezca lo que regresó hoy lo que va a llevar mañana de inicio . con un editable para de ahí cargarle más ... Y obviamente con un buscador para agregarle otros productos." Decision (L6): settlement keeps returning goods to the warehouse. A «Liquidada» assignment offers «Preparar siguiente reparto», which opens «Nuevo reparto» for the same rider prefilled with the returned quantities per product (editable, removable), with the search to add other products. Products no longer available are capped to what is available or flagged. If the rider already has an «En ruta» assignment the action explains it (use «Recargar»).
- **S6 — Row actions menu.** User: "crea un boton de acciones con ... que despliegue las acciones posibles". Each row of «Repartos de hoy» has one «⋯» (more) button opening a menu with the actions allowed for its state: En ruta → Recargar, Liquidar, Cancelar; Liquidada → Preparar siguiente reparto; Cancelada → none (no button). Accessible (keyboard, aria label «Acciones de <repartidor>»).
- **S7 — Edit a pending supplier order.** User (L9): yes to editing where it is worth it. A supplier order in «Pedido» (not received, not cancelled) can be edited from its detail: raise, lower or remove line quantities and add other products of the same supplier with a search; it keeps its folio. Line costs follow the same rules as creating an order; totals and any applied supplier-balance discounts stay consistent with the creation rules (a discount can never exceed the new payable; reopen what no longer fits). Cannot leave the order without lines (use «Cancelar pedido»). Received or cancelled orders cannot be edited. Rejections change nothing.
- **S8 — Edit the load of an en-route assignment.** User (L9). Next to «Recargar», an «En ruta» assignment offers «Editar carga»: lower or remove line quantities (units go back to their lots, keeping lots.reserved consistent) and raise/add like a recarga. Cannot leave the assignment empty (use «Cancelar»). Only «En ruta». Rejections change nothing. Settlement afterwards uses the edited quantities.
- **S9 — Rider dialogs look like «Nuevo pedido».** User: "conviene que este dialog para agregar productos a un reparto lo hagas un poco mas similar a este [Nuevo pedido], creo que asi esta en otras partes". «Nuevo reparto», «Recargar reparto» and «Editar carga» use the counter new-order layout: large dialog with maximize/restore, a search bar («Buscar por nombre o SKU») with the «Proveedor» select (LALA by default) and a «Solo agregados (N)» toggle on one row, and a table of every assignable product (image, name, SKU · N piezas por caja · proveedor, «Disponible: …») with Cajas/Unidades inputs per row (disabled without stock). No prices (nothing is charged until settlement). Footer summarizes what goes out (e.g. «N productos · X cajas y Y unidades») next to the main action. Behaviour, validation and server calls stay the same.
